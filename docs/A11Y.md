# Accessibility verification — 19 October 2026

## Automated results

- axe-core: **0 violations** on Home, Method, Deploy history and a recorded race page at 1440px, plus the evidence drawer. Home/Method/Deploy history also pass at 390px and 320px.
- No horizontal document overflow at 390px or 320px on the three main routes. Wide method/result tables have their own scroll region.
- Production Lighthouse: **100 accessibility, 94 performance** using mobile simulated throttling. Full measured report: `docs/lighthouse.json`. This is a local run, not a score for a Deployxa-hosted URL.
- Browser errors: none in the production route/playback checks.
- Start/replay, final results, evidence dialog open/close and reduced-motion final results were exercised by the browser-check script.
- The actual homepage Start race self-race completed in all six lanes. It is a one-step self-check, not comprehensive coverage of every workflow. Its dated recording is retained with the benchmark fixtures.

Reports: `docs/a11y-results.json`, `docs/lighthouse.json`; screenshots in `docs/screenshots/`.

The first audit identified faint lane numbering and accessible names that did not include all visible text. Both were corrected before the zero-violation run. Google Fonts are now served locally, static assets use Brotli/gzip, and schema code is kept out of the browser bundle to improve loading.

## Still required before submission

- A **human keyboard-only pass** through every workflow, including the journey picker and results/evidence dialog.
- A **human VoiceOver or NVDA pass**. The virtual screen-reader engine is not that pass.
- Per-store manual agreement after original builder exports arrive. No agreement percentage or real participant result is claimed.
- Rerun the same gates on the final hosted URL.

Automated checks and a single journey self-race do not establish WCAG 2.2 AA conformance. Use `/method` for measurement limits.
